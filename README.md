# Grok Bot Local

Grok Build의 Rust 에이전트 코어를 직접 연결한 로컬 웹 앱입니다. 앱 전용 엔진이 봇 대화와 도구 실행을 담당하며, 화면은 Grok Bot의 데스크톱 구성을 참고했습니다. OpenAI 호환 모델 서버를 연결하고, 루틴으로 작업을 예약하며, 브라우저에서 로컬 작업 폴더의 텍스트 파일을 읽고 수정합니다.

## 실행

Node.js 22.12 이상이 필요합니다. 엔진 소스 빌드에는 Rust stable, C/C++ 빌드 도구, `pkg-config`, zlib 개발 파일, `unzip`, `ripgrep`이 필요합니다. 검증 환경은 Linux x86_64, Node.js 24, Rust 1.98입니다. 엔진은 프로젝트 안에 빌드되며 별도 Grok Build CLI 설치 과정은 없습니다.

```sh
npm install
npm run build:engine
npm run dev
```

`build:engine`은 고정한 Grok Build 소스와 `engine/Cargo.lock`으로 `.engine/grok-bot-engine`을 만듭니다. 첫 빌드는 Rust 의존성을 내려받고 컴파일하므로 시간이 걸립니다. Linux x86_64에서는 체크섬을 확인한 Protocol Buffers 컴파일러를 자동 준비합니다. 다른 환경에서는 `PROTOC`에 컴파일러의 절대 경로를 지정할 수 있으며, 해당 환경의 동작은 추가 검증이 필요합니다. 소스와 빌드 의존성이 변경되면 엔진을 다시 빌드하고 앱을 재시작합니다.

브라우저에서 `http://127.0.0.1:3000`을 엽니다. 포트를 바꾸려면 `PORT=3100 npm run dev`로 실행합니다.

네트워크에서 접속하려면 `HOST=0.0.0.0 npm run dev` 또는 빌드 후 `HOST=0.0.0.0 npm start`로 실행합니다. 이 컴퓨터의 IPv4 주소, 컴퓨터 이름, `<컴퓨터 이름>.local`로 접속할 수 있습니다. Tailscale DNS 등의 추가 이름은 `GROK_BOT_ALLOWED_HOSTS=devbox.example.net,other.example.net`으로 지정합니다. 호스트 이름은 대소문자와 마지막 마침표를 정규화하며, 동일 출처 검사는 유지합니다. 로그인 기능이 없으므로 신뢰하는 네트워크에서 사용합니다.

배포용 빌드를 같은 컴퓨터에서 실행하려면 다음 명령을 사용합니다.

```sh
npm run build
npm start
```

## 모델과 작업 폴더 연결

1. 왼쪽 아래 **설정**을 엽니다.
2. **모델**에서 Base URL과 Model ID를 입력합니다. 예를 들어 OpenAI의 기본 주소는 `https://api.openai.com/v1`입니다. 로컬 모델 서버의 주소는 해당 서버 설정을 따릅니다.
3. API 키가 필요한 서버는 키를 입력합니다. 저장된 키는 서버에만 보관하며 브라우저로 다시 보내지 않습니다.
4. **연결 테스트**로 `/models` 응답을 확인합니다.
5. **설정 저장**을 누릅니다. 모델 설정만으로 봇과 대화할 수 있습니다.
6. 파일을 사용할 때 **컴퓨터**에서 작업 폴더의 절대 경로를 입력하고 저장합니다. 파일 도구는 연결한 작업 폴더 안에서 동작합니다.

API 기본 주소에는 `/chat/completions`를 붙이지 않습니다. 모델은 Chat Completions 스트리밍과 함수 도구 호출을 지원해야 합니다. 키 없는 로컬 서버에는 코어의 시작 인증을 위해 비밀이 아닌 Bearer 값을 보냅니다. 헤더 자체를 거절하는 로컬 서버는 별도 호환 설정이 필요합니다. 실제 공급자별 호환성은 사용하는 주소와 모델로 확인해야 합니다.

## 대화와 파일 편집

- 사이드바의 **+**로 봇을 만듭니다. 이름·지침·14가지 아바타 모양·11가지 색상을 설정합니다. 봇의 추가 작업 메뉴에서 고정하거나 숨기고, 컴팩트 보기로 전환할 수 있습니다.
- 하단 입력창에서 Enter로 메시지를 보냅니다. Shift+Enter는 줄바꿈입니다.
- 상단 **새 대화**로 대화를 나눕니다. 상단 **대화 기록**에서 이전 대화를 확인합니다. 원본에 없는 별도 최근 대화 섹션은 표시하지 않습니다. 실행 중인 작업은 **작업 중단**으로 취소합니다.
- 대화와 루틴 주소는 `?bot=…&conversation=…` 형태의 쿼리 매개변수를 사용합니다. 새로고침과 브라우저 뒤로·앞으로 이동 시 선택한 대화를 유지합니다.
- 여러 단계 작업에서 봇이 만든 **할 일** 목록을 답변 위에서 확인할 수 있습니다. 대기·진행 중·완료·취소됨 상태와 완료 개수를 표시하고, 제목을 눌러 접거나 펼칩니다. 마지막 목록은 새로고침·서버 재시작 뒤에도 남으며, 다음 턴이 시작되면 비웁니다. 목록은 봇의 진행 보고이며 사용자가 직접 체크하는 입력란은 아닙니다. [동작과 검증](docs/todos.md)을 참고하세요.
- 상단 봇 이름을 누르면 **세부 정보 / 라이브러리 / 컴퓨터** 패널이 열립니다. **라이브러리**에서 대화에 사용한 파일을 선택하면 실제 편집기가 열립니다. 상단 **컴퓨터** 버튼이나 입력창의 **+**로 작업 폴더를 엽니다.
- 텍스트 파일을 선택하고 내용을 편집한 뒤 **저장**을 누릅니다. 저장은 실제 디스크에 반영됩니다.
- AI가 제안한 파일 생성·수정은 대화의 승인 카드에서 내용을 확인한 뒤 한 번씩 승인합니다. 거절하면 파일을 변경하지 않습니다.
- 파일이 외부 편집기에서 변경되면 오래된 내용의 저장을 거절합니다. 입력 내용을 복사한 뒤 새로고침해 충돌을 해결합니다.

## 비공개 스킬

사이드바의 **앱 연결 → 내 플러그인**에서 선택한 봇의 비공개 스킬을 관리합니다. **스킬 추가**로 이름·사용 조건·Markdown 지침을 작성하고 저장합니다. 목록에서 사용 여부를 바꾸거나 스킬을 열어 수정·삭제할 수 있습니다. 다른 창의 변경과 충돌하면 초안을 유지하며 최신 버전을 다시 불러오도록 안내합니다.

**SKILL.md 가져오기**는 브라우저에서 선택한 UTF-8 Markdown 파일을 읽습니다. YAML 앞부분의 `name`과 `description`, 본문의 전체 지침을 저장합니다. 파일은 최대 20 KiB이며 스킬 텍스트의 JSON 인코딩 크기는 최대 18 KiB입니다. 이름은 영문 소문자·숫자·하이픈 64자, 설명은 1,024자까지 지원합니다. 도구·스크립트·모델·훅 설정은 거절합니다. 직접 작성하는 스킬은 이름 100자, 설명 2,000자까지 지원합니다.

**봇에게 만들기 요청**은 기존 작성 내용을 보존하고 대화 입력창에 요청을 준비합니다. 직접 보내면 봇이 전체 내용을 제안하고, **Save skill once**로 승인한 스킬만 저장합니다. 활성 스킬은 해당 봇의 이후 대화와 루틴에서 앱 도구를 통해 읽을 수 있습니다. 스킬은 기존 파일·컴퓨터·메시지 승인을 유지하며 실행 권한을 추가하지 않습니다. 봇 간 수신 대화는 대화 전용입니다.

봇당 최대 100개, 활성 스킬 전체 지침은 128 KiB로 제한합니다. 외부 커넥터 계정 인증·설치, 스킬 게시·공유, 실행형 워크플로는 아직 구현되지 않았습니다. 실제 모델의 자율적인 스킬 선택·준수는 사용하는 공급자에서 추가 확인이 필요합니다. 원본 화면과 소스 조사 결과는 [스킬 조사 기록](docs/skills-gap-audit.md)에 정리했습니다.

## 봇 간 대화

봇에게 다른 봇으로 메시지를 보내도록 요청할 수 있습니다. 봇 목록 조회와 메시지 전달 도구는 Grok Build 엔진이 앱의 도구 브로커에서 찾습니다. 보내기 전 승인 카드에서 받는 Bot과 전체 내용을 확인합니다. 승인한 메시지는 디스크에 저장한 뒤 수신 Bot의 지침으로 실행하고, 최종 답변 한 번을 두 봇의 대화에 기록합니다. 메시지 요약을 누르면 입력창이 없는 읽기 전용 대화를 엽니다.

수신 대화는 파일·컴퓨터 접근이 없는 대화 전용입니다. 추가 전달도 새 승인이 필요하며 한 실행의 고유 발신 메시지는 하나, 전달 체인은 네 단계로 제한합니다. 루틴과 같은 전역 실행 슬롯을 사용합니다. 대기 중인 전달은 재시작 후 처리하고, 이미 시작한 전달은 중단 상태로 남습니다.

일반 1:1 대화에서 보낸 메시지에 수신 Bot이 답하면(실패·중단 포함) 보낸 Bot이 원래 대화에서 한 번 더 자동으로 이어서 답합니다. 대화에는 "○○의 답변을 받아 이어서 답함" 표시와 이어진 답변만 보이고, 메시지 요약에는 대기 중·답변 중·답변 도착 상태가 표시됩니다. 이 후속 답변에서의 파일 쓰기, 메시지 보내기 등 모든 쓰기·외부 작업은 "묻지 않고 허용" 규칙이 있어도 매번 승인을 묻습니다. 중지하면 후속 답변은 다시 실행되지 않습니다. 후속 답변은 한 단계만 이어집니다. 수신 Bot이 다른 Bot에게 전달한 답은 보고되지 않으며, 한 전달 체인에서 후속 답변은 최대 두 번입니다. 이 기능을 처음 쓰는 시점에 이전 `state.json`을 `state.json.pre-bot-reports.bak`으로 한 번 보관합니다.

후속 답변이 아직 **대기 중**이면 메시지 요약의 **취소**로 이 대화의 대기 중인 이어서 답하기를 모두 취소할 수 있습니다. 상태가 **취소됨**으로 바뀌며, 이미 받은 답변과 원래 대화는 그대로 남습니다. 취소는 서버 재시작 뒤에도 유지됩니다. 이미 답변 중인 후속 턴은 기존 **작업 중단**을 사용합니다.

## 관리형 브라우저 컴퓨팅

서버 컴퓨터에서 `http://localhost:3000`에 접속하고 **컴퓨터** 탭을 엽니다. 허용할 공개 사이트의 출처 주소를 입력하고 **브라우저 시작**을 누르면 개인 브라우저와 분리된 Chrome이 열립니다. 주소 이동, 화면 클릭, 텍스트 입력, 키 입력, 스크롤, 화면 확대, 중지를 제공합니다. 모델이 페이지의 조작 요소를 읽거나 행동하려면 매번 localhost 연결에서 승인해야 합니다. 모델에는 페이지 주소와 조작 요소의 텍스트·좌표를 전달합니다. PNG 화면은 로컬 미리보기에서 사용합니다.

Google Chrome과 동작하는 호스트 샌드박스가 필요합니다. 샌드박스 검증 실패 시 시작을 차단합니다. 허용한 공개 사이트만 접근하며 사설 주소, 로그인 입력, 업로드·다운로드, WebSocket과 WebRTC, 개인 데스크톱 제어를 차단합니다. 읽기 중심의 제한된 웹 탐색 기능이며 일반 브라우저의 전체 호환성을 제공하지 않습니다. 네트워크 접속에서는 컴퓨터 제어가 비활성화되고 기존 채팅·파일 편집은 유지됩니다. 승인 전 로컬 컴퓨터 요청과 도구 상세는 네트워크 상태 응답에서 숨깁니다. 승인 후 모델 답변은 기존 대화 기록으로 공유됩니다. 인증 없는 리버스 프록시로 공개하지 마세요.

## 사용자 지정 MCP 서버와 보관함

Rust 서버에서는 Bot 세부 정보의 **사용자 지정 MCP 추가**로 로컬 명령 또는 원격 URL 서버를 하나씩 입력할 수 있습니다. 환경 변수·헤더는 보관함 시크릿을 선택하거나 새 값을 시크릿으로 저장하며, **연결 테스트**로 저장 전에 초기화와 도구 목록을 확인합니다. 새 서버는 꺼진 상태로 추가됩니다. 전체 구성은 기존 **MCP 서버 JSON**에서 계속 편집할 수 있습니다.

추가·테스트·켜기와 시크릿 변경은 서버 컴퓨터의 localhost 연결에서만 가능합니다. 자세한 검증 제한, 저장 실패 시 시크릿 처리, LAN 정책 및 API는 [MCP 서버 입력 폼](docs/mcp-server-form.md)을 참고하세요.

## 루틴

1. 사이드바의 **루틴**을 열고 **루틴 만들기**를 누릅니다.
2. 이름, 실행할 봇, 실행할 지시를 입력합니다.
3. **한 번**, **일정 간격**, **매일** 중 일정을 선택합니다. 매일 실행은 `Asia/Seoul` 같은 시간대를 함께 저장합니다.
4. **루틴 저장**을 누릅니다. 다음 실행 시각과 실행 기록이 표시됩니다.

**지금 실행**으로 수동 실행하고, **일시정지**와 **다시 시작**으로 예약을 제어합니다. 실행 기록의 **대화 보기**에서 결과를 확인하고 후속 대화를 이어갑니다. 루틴을 삭제해도 이전 실행 기록과 대화는 유지합니다. 대기 중인 루틴은 연결된 대화에서 중단할 수 있습니다.

서버가 실행 중일 때 예약을 처리합니다. 전체 봇에서 한 작업씩 실행하며, 같은 루틴의 대기·실행 작업은 하나로 제한합니다. 서버 중단 동안 놓친 반복 일정은 한 번으로 합칩니다. 실행을 시작한 작업은 재시작 시 중단 상태로 남고, 자동 재실행하지 않습니다. 대기 상태로 저장된 작업은 재시작 후 이어서 처리합니다. 파일 수정은 루틴에서도 브라우저 승인이 필요합니다. 예약 실행은 저장된 모델 설정을 사용하므로 연결한 공급자의 요금이 발생할 수 있습니다.

루틴은 최대 1,000개, 실행 기록은 최대 10,000개이며 상태 파일은 64 MiB로 제한합니다. 기존 기록을 자동 삭제하지 않습니다. 자세한 예약·복구 동작은 [docs/routines.md](docs/routines.md)에 정리했습니다.

## 로컬 실행과 보안 범위

웹 서버와 앱 전용 엔진은 파일이 있는 컴퓨터에서 실행해야 합니다. 기본 바인딩은 `127.0.0.1`이며 `HOST=0.0.0.0`으로 네트워크 접속을 활성화합니다. 연결한 브라우저는 서버 컴퓨터의 파일을 편집합니다.

작업 폴더 아래의 UTF-8 일반 텍스트 파일을 지원합니다. 직접 여는 파일의 크기 제한은 1 MiB입니다. AI의 파일 생성·수정 제안은 전체 내용을 확인할 수 있도록 160 KiB로 제한합니다. 경로 이탈, 심볼릭 링크, 하드 링크, 바이너리 파일을 거절합니다. 에이전트는 앱의 제한된 MCP 파일 도구를 사용합니다. 대화에 붙여 넣은 `@경로`, 이미지 경로 표기, `/명령`은 일반 메시지로 전달하며 파일을 자동 첨부하거나 네이티브 명령을 실행하지 않습니다. 이 버전은 셸 실행, 원격 데스크톱 제어, 외부 플러그인 설치를 제공하지 않습니다.

설정·대화·Grok 실행 세션은 기본적으로 `~/.local/share/grok-bot-q`에 저장됩니다. `GROK_BOT_DATA_DIR`로 다른 위치를 지정할 수 있습니다. API 키가 포함된 상태 파일은 사용자 전용 권한으로 저장됩니다. OS 비밀 저장소를 사용하는 암호화 보관 기능은 포함되지 않습니다. 앱 데이터 폴더를 작업 폴더로 연결하지 않습니다.

엔진은 앱 전용 HOME과 설정을 사용합니다. 기존 사용자의 Grok 로그인·설정·대화 파일은 그대로 유지됩니다. 엔진 소스가 바뀌면 기존 화면 기록을 보존하고, 새 실행 세션에 최근 사용자·봇 메시지를 최대 64 KiB까지 전달합니다. 이전 도구 실행을 자동 반복하지 않습니다. 앱을 종료해도 이미 승인해 저장한 파일 변경은 유지됩니다. 중단은 변경 취소 기능이 아닙니다.

이 앱은 개인용 로컬 실행을 대상으로 합니다. 공개 포트나 리버스 프록시를 통한 인터넷 공개에는 별도의 인증과 배포 보안 설계가 필요합니다.

## Rust 서버 (전환 중)

백엔드를 Rust로 옮기는 중입니다. 설계와 진행 상황은 [docs/rust-migration.md](docs/rust-migration.md)에 있습니다. Rust 서버는 같은 화면과 데이터 폴더를 사용하며, 관리형 Chrome도 같은 보호 조건으로 제공합니다.

```sh
npm install
npm run build          # 프론트엔드 dist/
npm run build:server   # Rust 서버 (엔진 포함)
HOST=0.0.0.0 PORT=7777 ./target/debug/grok-bot
```

`npm run test:rust`는 Rust workspace 테스트를, `npm run test:e2e:rust`는 Rust 서버를 대상으로 브라우저 테스트를 실행합니다. 처음 빌드할 때는 Rust 의존성을 컴파일하므로 시간이 걸립니다.

7777 서버를 상시 운영하려면 [release 사용자 서비스·백업·업데이트 안내](docs/server-operations.md)를 따릅니다. `node scripts/service.mjs install`로 release 실행·부팅 자동 시작·journald 로그를 구성하고, 이후 `node scripts/service.mjs update` 한 번으로 빌드 → 답변 실행 차단 → 데이터 백업 → 재시작 → 상태 확인을 수행합니다. 기존 debug 서버의 첫 전환과 lingering 설정은 안내의 준비 절차가 필요합니다.

## 검증 명령

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
```

테스트는 임시 작업 폴더와 로컬 OpenAI 호환 모의 서버를 사용합니다. `npm run build:engine`으로 만든 실제 앱 엔진을 사용하는 통합 테스트도 포함합니다. API 키나 유료 모델 호출은 필요하지 않습니다. 엔진이 없으면 실제 엔진 통합 테스트가 실패하므로 먼저 빌드해야 합니다.

브라우저 테스트는 Chromium을 사용합니다. Google Chrome이 설치되어 있어야 합니다. 테스트 출력은 `/tmp/grok-bot-playwright-results`에 저장됩니다.

## 구현 범위와 출처

화면은 허가받은 Mac에서 실행 중인 Grok Bot 0.78.1의 접근성 UI·패널 치수·읽기 전용 탐색을 관찰해 직접 구현했습니다. 이전 0.18 스크린샷은 보조 자료로 사용했습니다. 관찰 범위는 [UI 조사 기록](docs/grok-bot-ui-audit.md)에 남겼습니다. 원본 renderer 번들·폰트·이미지 자산은 포함하지 않습니다. 사용자가 화면 기록 권한을 허용한 뒤 원본 창의 채팅·우측 패널·설정·새 봇·컴팩트 화면을 캡처해 색상과 간격을 비교했습니다. 로컬 기능 확장·시스템 폰트·독립 아바타와 미관찰 상태의 차이가 있어 제품 전체의 픽셀 동일성은 보장하지 않습니다.

앱 엔진은 [Grok Build 소스 `2bdd1d6a6369`](https://github.com/xai-org/grok-build/tree/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8)의 `xai-grok-shell` 라이브러리를 직접 사용합니다. 앱 소유 진입점은 `engine/src/main.rs`에 있습니다. Apache-2.0 라이선스와 원본 고지는 `engine/licenses/`와 빌드 결과의 `.engine/licenses/`에 보존합니다. 통합 경계는 [docs/source-engine.md](docs/source-engine.md)에 정리했습니다.
