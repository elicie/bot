# Bot별 실행과 영속 대기열

이 문서는 [이슈 #20의 동작 규칙](https://github.com/elicie/bot/issues/20#issuecomment-6593783752)에 따른 Rust core 계약입니다. 화면 전환은 별도 UI PR에서 적용합니다.

## 실행 소유권과 순서

- 직렬화 단위는 실제 **발언 Bot**입니다. 사용자 메시지, 루틴, Bot 전달, 그룹 멤버, 후속 보고가 같은 Bot의 FIFO를 공유합니다. 그룹 ID나 대화 ID로 Bot 자리를 대신하지 않습니다.
- `workQueue` 벡터의 **저장된 순서**가 접수 순서입니다. 동일 시각, 대화 생성 순서, 시계 역행으로 기존 접수 순서를 다시 정렬하지 않습니다. 기존 전용 claim의 마이그레이션만 과거 시각과 대화 순서로 안정적으로 초기화합니다.
- 서로 다른 Bot은 동시에 실행합니다. `settings.maxConcurrentRuns`는 기본 **3**, 허용 범위 **1–16**입니다. 같은 Bot이 바쁘거나 상한에 도달하면 요청을 디스크에 접수하고 기다립니다. `RUN_BUSY`로 거절하지 않습니다.
- 현재 실행은 `Conversation.run.botId`에 실제 Bot을 기록합니다. 레거시 그룹 실행은 마지막 assistant의 `speakerBotId`로 소유자를 판별합니다. 대화당 현재 실행과 세션은 하나씩 유지합니다.
- 그룹은 한 멤버의 발언 동안만 그 Bot의 자리를 사용합니다. 다음 멤버는 앞 발언이 끝나야 실행 가능하며, 다음 라운드의 사용자 메시지는 앞 라운드 완료를 기다립니다. 이 의존성 때문에 아직 실행 불가능한 다음 라운드가 앞 라운드의 멤버를 가로막지는 않습니다.

## 접수·디스패치·복구

일반 메시지는 텍스트와 첨부 메타데이터를 대기 레코드로 저장합니다. 첨부 바이트는 기존 private blob 경로에 먼저 저장합니다. 대기 중인 입력은 진행 중인 엔진 세션에 섞거나 현재 run을 덮어쓰지 않습니다.

루틴·전달·그룹·보고는 기존 내역을 진실의 원천으로 두고 대기열에서 그 내역을 가리킵니다. 변경을 저장할 때 새로 준비된 claim을 같은 FIFO의 끝에 붙이고, 이미 시작하거나 취소된 포인터는 제거합니다. 보고는 대화당 한 포인터가 가장 먼저 접수된 체인을 고정합니다.

디스패처는 각 Bot의 실행 가능한 첫 항목만 선택해 빈 전역 자리를 채웁니다. 대기열 제거와 `starting` 실행 생성은 한 번의 원자적 상태 저장으로 처리합니다. 재시작 시 이미 시작한 실행은 기존처럼 `interrupted`로 남고 다시 재생하지 않으며, 시작하지 않은 대기 항목은 같은 ID와 순서로 복구합니다.

새 저장 형식의 첫 기록 전 `state.json.pre-work-queue.bak`을 사용자 전용 권한으로 한 번 보관합니다. 이 버전의 대기열·실행 소유자·상한을 기록한 상태는 이를 모르는 구버전으로 직접 열지 않습니다.

## 체인·Stop·승인

- `waiting_children`은 **전달의 집계 상태**이며 실행 중인 엔진 턴이 아닙니다. 기다리는 부모는 Bot 자리나 전역 자리를 소유하지 않습니다. 따라서 상한이 1이어도 A→B→A 전달과 역방향 후속 보고가 진행할 수 있습니다.
- 일반 Stop은 **선택한 대화의 현재 실행과 대기 작업**만 취소합니다. 같은 Bot의 다른 대화나 다른 Bot의 실행을 취소하지 않습니다. 이전의 체인 전체 Stop 동작을 대화 범위로 바꾼 것은 이슈의 명시적 규칙에 따른 변경입니다.
- `POST /api/conversations/:id/queued-turns/:turnId/cancel`은 아직 대기 중인 사용자 요청 **하나**를 제거합니다. 이미 시작한 ID는 404이므로, 화면에서 늦게 누른 대기 취소가 새 실행을 중단하지 않습니다.
- 체인 전체 30분 기한은 유지합니다. 기한 만료는 해당 체인을 오류로 끝내는 별도 안전 장치이며, 사용자 Stop과 구분합니다.
- 승인 FIFO와 취소 신호는 각 Run에 속합니다. 브로커는 run ID와 토큰, 엔진 이벤트는 session ID로 라우팅합니다. SSE는 모든 대화와 대기열이 포함된 리비전 스냅샷을 전달하며 로컬 전용 승인 상세는 기존처럼 원격 클라이언트에서 가립니다.
- 같은 공급자 엔진 호스트를 여러 세션이 공유합니다. 한 세션을 취소할 때 호스트를 종료하지 않습니다. 이벤트 drain은 무한히 비워질 때까지 기다리지 않고 유한한 수신 접두 구간을 처리하여 다른 세션의 계속되는 스트림이 종료 처리를 굶기지 않게 합니다.

## 변경 잠금

모델·공급자·API 키·작업 폴더, 유지보수 및 공유 파일/컴퓨터 작업의 보호 조건은 앱 전체 실행이 쉬어야 한다는 기존 조건을 유지합니다. Bot의 지침·스킬·메모리·지식·MCP 설정과 Bot 범위 시크릿은 해당 Bot만 쉬면 변경할 수 있습니다. 전역 시크릿은 모든 Bot에 영향을 주므로 전역 idle이 필요합니다.

Bot 삭제는 해당 Bot의 실행뿐 아니라 삭제 영향 범위의 대기 사용자/전달/보고/그룹 발언이 없어야 합니다. 이미 접수한 작업을 몰래 버려 삭제를 통과시키지 않습니다. 관련 없는 Bot의 실행은 삭제나 설정 변경을 막지 않습니다.

## 단계와 검증

Core PR은 이 계약과 Rust 회귀 테스트를 제공하며, UI PR은 다른 Bot 전송, 대기 표시/개별 취소, 사이드바 상태와 동시 승인/e2e를 적용합니다. Core만 적용한 단계의 기존 화면은 여전히 전역 전송 제한을 표시할 수 있습니다.

변경한 model/store/core 크레이트와 관련 스펙만 검사합니다. 새 실제 엔진/로컬 공급자 회귀 테스트는 두 Bot 동시 실행, 같은 대화와 다른 대화의 같은 Bot FIFO, 기본/변경 상한, 대화별 Stop, 혼합 사용자/루틴 순서, 그룹 멤버 충돌, 재시작 복구 및 상한 1의 실제 A→B→A 전달/보고를 다룹니다. 테스트 존재는 실행 결과와 구분하며, 실제 실행 결과는 PR 설명에 기록합니다.
