# 원격 MCP OAuth

[이슈 #15](<https://github.com/elicie/bot/issues/15>)의 원격 MCP 로그인 기능입니다. **실제 계정의 동의와 인증된 도구 호출 검증 전까지 전체 완료로 간주하지 않습니다.** 기존 stdio·수동 HTTP 헤더·시크릿 참조 방식은 그대로 유지합니다.

## 연결

1. 서버 컴퓨터의 `localhost`에서 앱을 열고, Bot의 세부 정보 → MCP 서버에 HTTPS 서버를 추가합니다.
2. 서버 행의 **로그인**을 누릅니다. 자동 등록을 지원하면 클라이언트 ID를 비워 둡니다. 브라우저에서 직접 동의하며 앱이나 모델에 계정 비밀번호를 입력하지 않습니다.
3. 리소스 식별자가 전송 주소와 다르면 선택 항목에 명시합니다. 예를 들어 Notion 전송 주소가 `https://mcp.notion.com/mcp`이면 리소스는 `https://mcp.notion.com`입니다. 같은 출처와 포함 경로만 허용하며, 반환된 `resource`의 일치 검증을 느슨하게 하지 않습니다.
4. 연결 상태가 **연결됨**이 된 뒤 필요한 경우 서버 사용 스위치를 별도로 켭니다. 로그인은 서버를 자동으로 켜지 않으며 기존 도구 호출 승인 규칙도 유지됩니다.

수동 ID는 공개 클라이언트와 RFC 9207 issuer 응답을 지원하는 공급자만 허용합니다. 공급자에 `http://127.0.0.1/mcp-oauth/callback` 경로를 등록하고 RFC 8252에 따라 loopback 포트 변경을 허용해야 합니다. 자동 등록은 매 시도마다 별도의 무작위 콜백 경로를 등록합니다. 인증 서버나 등록 방식이 이 초기 프로필과 맞지 않으면 평문 토큰·클라이언트 시크릿으로 우회하지 않습니다.

콜백은 서버 컴퓨터의 `127.0.0.1` 임시 포트에만 열리므로 다른 컴퓨터의 브라우저로 인증을 끝낼 수 없습니다. LAN에서는 로그인·로그아웃을 서버가 실제 소켓 주소로 거절하며, 전달 헤더는 신뢰하지 않습니다. 실행 중에는 계정 변경을 거절합니다. 로그인 동의를 기다리는 동안 전역 명령 큐를 점유하지 않습니다. UI의 자동 확인이 끝난 뒤 로그인했다면 인증 상태 새로고침을 누릅니다.

## 자격 증명 보호

[서비스](<../crates/core/src/mcp_oauth/service.rs>)는 OAuth 자격 증명을 일반 상태 파일이나 MCP JSON에 넣지 않습니다. [별도 보관소](<../crates/core/src/mcp_oauth/vault.rs>)의 `mcp-oauth/credentials.enc`에 AES-256-GCM으로 저장합니다. 임의로 생성한 키는 같은 소유자 전용 디렉터리의 `master.key`에 별도로 보관합니다. 디렉터리 0700·파일 0600, 링크·소유권 검사, 원자적 쓰기와 fsync, 단일 작성자 잠금을 사용하며 잘못된 키·변조·삭제·안전하지 않은 권한은 실패 처리합니다. 저장 오류를 토큰 삭제나 평문 저장으로 바꾸지 않습니다.

**보호 범위:** 이는 실수로 토큰 평문이 파일이나 백업에 섞이는 일을 막는 로컬 파일 암호화입니다. OS 키체인이나 별도 잠금 비밀번호를 제공하지 않으며, 같은 사용자 권한의 프로세스나 키와 암호문을 함께 탈취한 공격자로부터 보호하지 않습니다. 백업·복구 시 두 파일을 함께 보존하고 접근을 제한해야 합니다. 잘못된 보관소를 초기화하지 않고 시작을 중단하므로, 원본을 보존한 상태에서 올바른 키·권한·암호문을 복구해야 합니다. 기존 수동 보관함·모델 API 키의 저장 형식은 변경하지 않습니다.

공개 상태·SSE·모델에 전달되는 텍스트에는 서버 전용 가리기 목록을 적용합니다. 모델 응답도 앱의 공급자 중계기에서 네이티브 엔진에 보내기 전에 검사하므로, 청크에 걸친 토큰이나 도구 인자의 JSON 이스케이프가 엔진 파일·이어지는 세션 기록으로 들어가지 않도록 합니다. 등록된 OAuth 비밀이 없을 때는 기존 모델 응답 경로를 바꾸지 않습니다. 현재 토큰과 최대 256개 과거 비밀 값은 암호화 보관소에 유지해 갱신·로그아웃·재시작 뒤 늦게 도착한 응답을 가립니다. 따라서 로그아웃은 사용 가능한 계정 연결을 제거하는 것이며 과거 값의 보안 삭제를 약속하지 않습니다.

## 실행·갱신·로그아웃

- Bot·서버 ID·이름·구성 지문·정확한 전송 주소에 자격 증명을 묶습니다. 구성 변경과 삭제 뒤 오래된 콜백이나 준비 결과를 재사용하지 않습니다. 삭제된 대상과 명시적으로 저장한 수동 인증·stdio 전환은 로컬 연결을 정리하며, 새 HTTPS 대상으로 바꾼 구성은 다시 동의를 요구합니다. 정리한 비밀 값은 제한된 가리기 이력에만 남습니다.
- 대화 시작 전에 만료가 가까운 토큰을 갱신하고, 현재 issuer와 토큰 엔드포인트를 다시 검증합니다. 한 턴에서는 그 토큰을 고정합니다. 긴 승인 대기 중 만료되면 다시 로그인을 안내하며 도구 POST를 자동 재실행하지 않습니다.
- [턴 전용 loopback 중계기](<../crates/core/src/mcp_oauth/relay.rs>)를 통해 실제 OAuth 토큰 대신 임시 로컬 인증 값만 엔진에 전달합니다. 중계기는 원래 HTTPS 대상과 검증한 공개 DNS 주소에만 연결하며 프록시·리다이렉트를 따르지 않습니다. JSON/SSE 결과의 비밀 값도 모델에 보내기 전에 가립니다. 턴 종료·취소 시 소켓과 스트림을 닫습니다.
- 실제 리소스의 401 또는 갱신 거절은 **다시 로그인** 상태가 됩니다. 오래된 턴의 401은 새로 갱신한 토큰이나 새 로그인을 무효화하지 않습니다. 일반 네트워크 오류를 토큰 철회라고 단정하지 않습니다.
- 로그아웃은 로컬 연결을 제거하고 진행 중인 인증을 취소합니다. 검증된 공개 클라이언트용 철회 엔드포인트가 있으면 제한된 시간 동안 철회를 요청합니다. 공급자 측 철회 성공을 확인할 수 없으면 성공했다고 주장하지 않습니다.

## HTTP 계약

| 메서드 | 경로 | 본문 / 응답 |
| --- | --- | --- |
| GET | `/api/bots/:botId/mcp-servers/:name/oauth` | `{status, canLogin, message?}`; 토큰·계정·URL 없음 |
| POST | 같은 경로 + `/login` | `{clientId?, resource?}` → `{authorizationUrl}`; 실제 loopback·idle 전용 |
| POST | 같은 경로 + `/logout` | `{}` → 인증 상태; 실제 loopback·idle 전용 |

오류는 기존 `{error}` 형식과 HTTP 상태를 사용하되 외부 응답 본문·URL·콜백 값을 전달하지 않습니다. 기존 MCP 설정·사용 스위치 응답과 공개 상태 형식은 바꾸지 않습니다.

## 초기 호환 범위

[디스커버리](<../crates/core/src/mcp_oauth/mod.rs>)는 경로·쿼리별 protected-resource well-known과 RFC 8414/OIDC 메타데이터를 조회합니다. 리소스·issuer는 JSON 이스케이프만 해제한 원문으로 비교하며, 불일치 응답 뒤 다른 리소스로 우회하지 않습니다. 메타데이터·사용할 엔드포인트는 HTTPS, 공개 주소, 제한된 크기·요청 수·대기 시간을 요구합니다. 사용하지 않는 확장 메타데이터는 무시합니다. PKCE는 명시적인 S256 지원을 요구합니다. 토큰 값은 전역 가리기 때문에 일반 문장 전체가 손상되지 않도록 기존 수동 보관함과 같이 최소 8바이트를 요구하며, 이보다 짧은 access/refresh 토큰은 저장·사용하지 않습니다. access 토큰은 불투명한 공급자 값으로 취급해 `userId:grantId:secret`처럼 콜론을 포함한 visible ASCII도 받습니다. 공백·제어 문자·비 ASCII·따옴표·쉼표·역슬래시는 Authorization 헤더 경계를 모호하게 하지 않도록 거절하며, 교환과 MCP 중계기는 같은 검사를 사용합니다.

모델 응답 필터는 이 앱의 네이티브 엔진과 같은 단일 선택(`n=1`) 응답을 요구합니다. 두 번째 선택 인덱스나 종료된 선택의 추가 텍스트는 거절하며, 엔진이 무시하는 확장 필드는 안전하게 생략합니다. 도구 이름은 완전한 마지막 값으로 취급하고 인자만 누적합니다.

아직 `WWW-Authenticate`의 `resource_metadata` 포인터, client-ID 메타데이터 문서, 기밀 클라이언트·클라이언트 시크릿 입력, 사용자 지정 scope 입력, 턴 중 자동 재인증은 지원하지 않습니다. 이 프로필이 모든 OAuth/MCP 공급자를 지원한다고 보지 않습니다.

## 검증

- [디스커버리 테스트](<../crates/core/src/mcp_oauth/tests.rs>): 잘못된 리소스·issuer, HTTPS·S256, JSON 형식과 생략값, 요청·응답·시간 제한.
- [서비스 테스트](<../crates/core/src/mcp_oauth/service_tests.rs>)와 내부 프로토콜/보관소 테스트: 합성 토큰으로 PKCE 콜백·등록·갱신·철회·취소·재시작·변조를 검증합니다.
- [소켓 HTTP 테스트](<../crates/core/tests/mcp_oauth.rs>): LAN 거절, 전달 헤더 위조, 실행 중 변경 거절과 응답 비노출.
- [브라우저 테스트](<../tests/vault-mcp.spec.ts>): 실제 앱의 기존 MCP 동작과 OAuth 상태·창 격리·LAN UI·오류·뒤늦은 응답을 검증합니다. 모의 OAuth 응답은 실제 계정 로그인을 대체하지 않습니다.
- 실제 공개 메타데이터를 읽는 opt-in 테스트는 로그인·토큰 발급·도구 호출 검증이 아닙니다. 최종 완료 조건은 사람이 직접 동의한 실제 MCP 서버에서 승인된 도구 호출의 성공과 비노출 확인입니다.
