# Verification

## Current Rust-only check commands

The current backend is the Rust server with an in-process engine library. Node.js 22.12+ is frontend/build/test tooling, not a release-runtime dependency. Run these commands from the checkout with the native build prerequisites in [README.md](<../README.md#실행>) installed:

```sh
npm run typecheck
npm test
npm run test:rust
npm run build
npm run build:server
npm run test:e2e
npm run build:release
node scripts/verify-release.mjs target/release/grok-bot
```

`npm test` retains frontend unit tests; `npm run test:rust` covers the Rust workspace backend and engine tests. Playwright uses Rust by default with no backend selection flag or Rust-only e2e alias. Its build order is frontend, debug server, then e2e. Fixtures use temporary data/workspaces and a local OpenAI-compatible provider, not paid model calls. Browser checks and managed computing require system Google Chrome and its working sandbox.

`build:release` runs `npm run build` followed by `node scripts/cargo.mjs build --locked --release -p grok-bot-server`. [crates/server/build.rs](<../crates/server/build.rs>) embeds the compiled [dist/](<../dist/>) for release builds. Release compilation must fail rather than produce a UI-less artifact when the frontend output is absent. Debug builds never embed frontend output: they serve [dist/](<../dist/>) in the current working directory, or run API-only when it is absent. Their build script does not watch frontend output. An explicit `GROK_BOT_WEB_ROOT` takes precedence and must contain `index.html`.

### Limits at the time

- The UI follows observed Grok Bot 0.78.1 window screenshots, accessibility geometry, and interactions. Captured states were visually compared and color/spacing/avatars refined; complete-product pixel equality remains unverified across fonts, independently drawn avatars, local feature extensions, and unobserved states. Original renderer bundles, fonts, and image assets are excluded.
- Provider compatibility was exercised against a local OpenAI Chat Completions fixture. The user's actual provider and credentials were not supplied or tested.
- The runtime requires the repo-built engine's exact app version and pinned upstream revision. Missing or mismatched artifacts fail closed with source-build instructions. Upstream CLI package version 1.0.45 is separate from app engine version 0.1.0.
- Source changes create replacement execution sessions with at most 64 KiB of recent visible context. Older history and previous tool state can be omitted; the full display transcript remains stored.
- The verified native artifact is an unoptimized local development build for this Linux host. Cross-platform release archives, older-glibc compatibility, reproducible binary hashes, and complete executable-distribution notices/source availability remain release work.
- Upstream still reads system configuration layers such as `/etc/grok`. Private application HOME/GROK_HOME/XDG directories isolate user-level configuration.
- File execution occurs on the backend computer. The server defaults to loopback and supports explicit `0.0.0.0` binding for a trusted network. It targets one local user and has no login.
- Direct text editing supports files up to 1 MiB. AI write proposals are limited to 160 KiB for complete review.
- This implementation provides application-level file confinement. Other programs running as the same OS user remain outside that boundary.
- Local routine scheduling requires the server to remain running. Started work becomes interrupted after restart; durable queued work resumes. Limits retain 1,000 routines, 10,000 execution records, and 64 MiB of state without automatic history pruning.
- Managed computing is a restricted, isolated Chrome with a verified sandbox. Start, manual control, preview, and model approvals require loopback access. Hosts without a working sandbox fail closed. No credentials, file upload/download, personal desktop, or cloud computer is supported. The app has no login, and a reverse proxy needs separate authentication. Approved observations and model answers may become part of the application's shared chat history.
- Windows and macOS execution has not been verified. Native desktop control, cloud computers, hosted multi-user access, group chats, encrypted arbitrary vault items, cloud billing/accounts, read/unread state, destructive bot deletion, and cloud-hosted scheduling remain outside this build.
