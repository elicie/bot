# Grok Bot 기능 차이 분석 (0.78.1)

작성일: 2026-11-01

## 근거

`elicie@mac-mini`에 설치된 Grok Bot 0.78.1(`com.anysphere.sand`, Electron 42)을 읽기 전용으로 조사했습니다.

- 실행 중인 프로세스의 등록 스킴: `sand-media`, `sand-canvas`, `sand-html-preview`, `sand-avatar`, `sand-mcp-app`, `sand-visualization`
- `app.asar`의 구성: `renderer`(화면), `node-agent-coordinator`(봇 실행 조정), `local-exec-daemon`(로컬 실행)
- 조정기 RPC 이름: `createGroup`, `setGroupMembers`, `setMainAgent`, `getSubagents`, `setAgentUnread`, `setAgentNotifyOnUpdates`, `setAgentHiddenFromSidebar`, `getAgentTasks`, `setAgentTaskPinned`, `createThreadFromMessage`, `readAttachmentText`, `readAttachmentImage`, `getAgentAutomations`, `runAutomationWebhook`, `createAgentFromTemplate`, `deleteAgent`, `readMcpAppResource` 등
- 화면 기능 묶음 이름과 한국어 문구 5,089개

원본 번들·자산·코드는 저장소에 포함하지 않습니다. 문구와 동작은 참고 자료로만 쓰고, 구현은 독립적으로 작성합니다. 원격 앱에서는 메시지 전송, 설정 변경, 클라우드 컴퓨터 깨우기를 하지 않았습니다.

## 2차 구현 결과: 보관함 시크릿과 사용자 지정 MCP

| 기능 | 원본 근거 (문구·청크) | 로컬 구현 |
| --- | --- | --- |
| 보관함 시크릿 | "Grok Bot 보관함", "보관함 검색", "새 시크릿 추가", "시크릿 값", "시크릿 붙여넣기", "값은 쓰기 전용입니다", "문자로 시작하는 대문자 환경 변수 이름(A-Z, 0-9, _)을 사용해 주세요", `grok-bot-secrets` | 모든 Bot 또는 Bot별 시크릿. 값은 `state.json`(0600)에만 저장하고 스냅샷·SSE·모델에 보내지 않음. 이름만 표시(마스킹), 교체·삭제. 운영체제 키체인 연동 없음 |
| 사용자 지정 MCP | "MCP 서버", "MCP 서버 JSON", "사용자 지정 MCP 추가", "JSON은 서버 이름을 키로 하는 객체여야 해요", "서버 이름은 비워 둘 수 없어요", "서버에는 URL 또는 명령이 필요해요", `custom-mcp-form` | Bot 세부 정보의 JSON 편집기. stdio(command·args·env)와 HTTP(url·headers). env·headers 값에서 `${secret:NAME}` 참조, 세션 시작 때 서버에서만 치환. 서버별 켜기·끄기(기본 꺼짐) |
| 도구 승인 | 권한 규칙 | 사용자 지정 도구 호출마다 승인 카드, 권한 범주 `mcp_tool`(서버 하나로 제한 가능)로 "묻지 않고 허용" |

원본과 다른 점과 이유:

- 원본은 서버를 한 번에 하나씩 추가하는 폼(HTTP/STDIO 선택)과 JSON 보기를 함께 둡니다("서버는 한 번에 하나씩 추가하세요"). 로컬은 Bot의 서버 전체를 JSON 문서 하나로 편집합니다.
- 원본의 stdio 명령은 클라우드 Box에서 실행되고 "시크릿이 필요한 서버라면 원격 HTTPS를 사용하세요"라고 안내합니다. 로컬 stdio 서버는 서버 컴퓨터에서 이 앱의 사용자 권한으로 실행되므로, 만들기·편집·켜기와 시크릿 변경은 localhost 연결에서만 할 수 있고 새로 추가하거나 바꾼 서버는 꺼진 상태로 저장합니다. LAN 접속은 이름과 요약만 보고 끌 수만 있습니다.
- 시크릿 값은 8자 이상이어야 합니다. 모든 공개 문자열에서 값을 가리기 때문에 짧은 값은 대화 내용을 망가뜨립니다.
- 사용자 지정 서버의 도구 결과는 모델에 그대로 전달됩니다. 서버가 자기 자격 증명을 결과에 넣으면 모델이 볼 수 있습니다(브라우저 표시는 가려짐).

원본에서 확인이 더 필요한 점: 시크릿 이름 규칙의 길이 제한, 시크릿 값 최소 길이 여부, 팀원에게 시크릿 이름이 보이는지, 사용자 지정 MCP 도구 호출이 원본에서 매번 승인을 묻는지와 서버별 허용 규칙 유무, OAuth 클라이언트 시크릿(선택사항) 흐름.

## 실제 모델 검증 (2026-11-02)

실제 OpenAI 호환 공급자(`gpt-6.1-sol`)와 임시 데이터 폴더로 Rust 서버를 띄워 API와 Chrome 화면으로 확인했습니다.

| 항목 | 결과 |
| --- | --- |
| 여러 턴 대화, 지침 유지, 재시작 후 이어가기 | 통과. 다시 불러온 뒤에도 지침 유지 |
| 파일 읽기·쓰기 승인과 거절 | 통과 |
| 대화로 Bot·루틴 생성, 루틴 일시 중지·지금 실행 | 통과 |
| 메모리, 지식 파일, 이미지·텍스트 첨부 | 통과 |
| 스레드, 그룹(순서·멘션), Bot 간 메시지 | 통과. Bot 간 답장은 비동기라 보낸 Bot은 같은 턴에 답을 모름 |
| 차트 요청 | 실패 → 수정. 공급자가 `images`만 담아 응답해 엔진이 빈 응답으로 처리했음 |
| 관리형 Chrome | 페이지 본문을 못 읽음 → 수정 |

수정 내용:

- 엔진은 서버 안의 loopback 중계기를 거쳐 공급자와 통신합니다. 중계기는 응답의 `images`를 `<data>/generated-images`에 저장하고 답변에 이미지 링크(`/api/generated-images/:id`)로 넣습니다. 실제 API 키는 엔진 설정 파일에 쓰지 않습니다.
- 세션 지침에서 차트를 `visualization`/`svg` 코드 블록으로 답하도록 안내합니다.
- 관리형 Chrome 관찰 결과에 화면에 보이는 본문 텍스트(최대 6000자, 입력값 제외, 신뢰하지 않는 데이터로 표시)를 넣습니다.
- 다른 답변이 실행 중일 때 보내면 그 상황에 맞는 오류를 보여 줍니다.

이후 수정: `**굵게**` 바로 뒤에 한글이 붙으면 굵게가 적용되지 않던 문제(`remark-cjk-friendly`), 그룹 삭제 시 그 대화와 스레드의 첨부 파일·엔진 세션이 디스크에 남던 문제.
