# 대화 캔버스

각 대화에 문서·코드 하나를 저장하고 Bot과 부분 수정하는 영역입니다. 기존 대화·작업 폴더·승인 계약을 바꾸지 않는 추가 기능이며 Node 기본 서버와 Rust 서버에서 제공합니다.

## 사용

1. 대화 상단의 **캔버스 열기**를 누릅니다. 대화가 없으면 먼저 새 대화를 만들며, 모델이나 작업 폴더 연결 없이도 사용할 수 있습니다.
2. 제목·형식·내용을 작성하고 **저장** 또는 Ctrl/Cmd+S를 누릅니다. 마크다운은 안전한 미리보기를 제공하고, 코드 형식은 실행 없는 일반 텍스트 편집입니다. HTML·스크립트·원격 이미지도 실행하거나 자동으로 불러오지 않습니다.
3. Bot에게 “이 문단을 더 짧게”처럼 요청합니다. Bot은 현재 저장된 내용과 버전을 읽고 수정 범위의 이전·이후 전체 텍스트를 승인 카드로 제안합니다. **Replace canvas once**로 승인한 뒤에만 반영됩니다. 저장하지 않은 브라우저 초안은 Bot에게 전달되지 않습니다.
4. **이전 버전으로 되돌리기**, 또는 **버전 기록 → 이 버전 복원**으로 복원합니다. 복원은 이전 번호로 되감기가 아니라 새 버전 저장입니다. Bot 수정과 사용자 수정 모두 같은 기록에 남습니다.
5. **캔버스 파일로 다운로드**는 현재 저장 버전을 브라우저 다운로드로 저장합니다. **작업 폴더에 저장 요청**은 현재 버전과 파일명을 확인하는 요청을 대화 입력창에 준비합니다. 직접 전송하면 Bot이 기존 파일 읽기·해시·`write_file` 승인 경로를 사용합니다. 기존 `file_write` 권한 규칙은 그대로 적용되며 새 디스크 쓰기 우회 경로는 없습니다. 캔버스 복원은 이미 내보낸 파일을 되돌리지 않습니다.

넓은 화면에서는 채팅과 나란히 보이고, 1000px 이하에서는 캔버스를 넓게 표시합니다. **대화로 돌아가기**로 초안을 보존한 채 승인·대화를 확인하고, 다시 캔버스를 열 수 있습니다. 닫기·다른 대화로 이동·새로고침은 저장하지 않은 변경을 경고합니다. 그룹과 스레드는 각각 자기 대화의 캔버스를 가지며 부모·다른 대화의 내용은 공유하지 않습니다. Bot 간 수신 전용 대화는 기존 대화 전용 제한을 유지합니다.

## 저장·충돌 계약

- `Conversation.canvas`는 선택 필드입니다. 기존 대화에는 없으며 첫 저장 때 생성됩니다.
- 현재 버전은 `{ revision, title, language, content, updatedAt, source, history }`입니다. `source`는 `user`, `bot`, `restore`; `history`는 과거 버전의 같은 필드에서 `history`를 뺀 형태입니다. 공개 응답에서 비밀 값이 가려지면 해당 현재/과거 버전에 `redacted: true`가 붙습니다.
- 내용은 UTF-8 128 KiB, 제목은 공백 정리 후 UTF-16 1–100자, 형식은 `[a-z][a-z0-9-]{0,31}`입니다. NUL·잘못된 유니코드는 거절합니다. 버전은 JavaScript 안전 정수 범위의 양의 정수입니다.
- 최근 과거 버전 **20개**와 현재 버전을 보관합니다. 따라서 오래된 기록은 보관 범위를 벗어나면 복원할 수 없습니다. 원문 내용은 과거 기록만 최대 약 2.5 MiB이며 JSON 이스케이프·메타데이터는 별도입니다. 기존 64 MiB 전체 상태 제한과 대기 작업의 기존 예약 용량을 저장 전에 검사합니다. 실패하면 현재 내용과 기록을 바꾸지 않습니다.
- 새 문서 저장은 기대 버전 `0`, 이후 저장·복원은 현재 버전과 정확히 일치해야 합니다. 충돌은 HTTP 409이며 자동 병합·덮어쓰기를 하지 않습니다. 동일한 내용·제목·형식의 전체 저장은 새 버전을 만들지 않습니다.
- 사용자 저장은 Bot 실행·승인 대기 중에도 가능합니다. Bot 승인은 큐를 잠그지 않고 기다리며, 승인 뒤 저장 락 안에서 원래 버전을 다시 비교합니다. 검토 중 사용자가 저장했으면 승인해도 Bot 수정은 반영되지 않습니다. 거절·중단·늦은 승인도 새 버전을 만들지 않습니다.
- 새 스냅샷은 깨끗한 편집기를 갱신하지만 초안을 덮어쓰지 않습니다. 충돌 초안은 내용을 복사한 뒤 **최신 버전 다시 열기**로 명시적으로 해결합니다. 비밀 설정 변경은 문서 번호를 바꾸지 않아도 공개 텍스트를 바꾸므로 이 경우도 저장 기준을 재확인합니다. 가려진 내용을 그대로 저장해 실제 원문을 잃는 동작은 차단합니다.
- 상태 파일은 기존 단일 서버 작성자 모델을 사용합니다. 다른 서버 프로세스를 같은 데이터 디렉터리에 동시에 띄우는 협업이나 CRDT/자동 병합을 새로 제공하지 않습니다.

## 추가 HTTP·Bot 인터페이스

| 인터페이스 | 입력 | 결과 |
| --- | --- | --- |
| `PUT /api/conversations/:id/canvas` | `{ revision, title, language, content }` | 저장된 공개 `AppState` |
| `POST /api/conversations/:id/canvas/restore` | `{ revision, targetRevision }` | 새 복원 버전의 공개 `AppState` |
| `workspace__read_canvas` | `{ offset?, revision?, viewHash? }` | `{ canvas: null }` 또는 현재 공개 문서의 완전한 한 페이지. `canvas` 안에 `offset`, `totalBytes`, `viewHash`, 선택적 `nextOffset`와 과거 버전 요약을 포함 |
| `workspace__replace_canvas_range` | `{ revision, oldText, replacement }` | 승인·저장 성공 뒤 `{ saved: true, revision }` |

Bot 읽기는 먼저 `{}`로 시작합니다. `canvas.content`는 현재 페이지의 본문이며, `nextOffset`이 있으면 그 값을 `offset`으로 보내고 첫 페이지의 `revision`과 `viewHash`를 함께 보내 이어 읽습니다. 오프셋은 **마스킹 후 공개 텍스트의 UTF-8 바이트** 기준이며 문자 중간 위치는 거절합니다. 모든 페이지의 완전한 JSON·이스케이프 결과를 18 KiB 이하로 제한해 엔진의 20,000바이트 잘림을 피합니다. 문서 버전 또는 비밀 설정으로 공개 내용이 바뀌면 409로 중단하며 처음부터 다시 읽어야 합니다. 전체 파일로 내보낼 때는 같은 버전·공개 내용의 모든 페이지를 순서대로 합친 뒤 기존 파일 승인 경로를 사용합니다. 과거 기록은 버전·작성 주체·시각·마스킹 표시만 보내고 과거 본문·제목은 보내지 않습니다.

기존 동일 출처 JSON·`X-Grok-Bot: 1` 보호와 상태/SSE 전달을 그대로 사용합니다. Bot은 인증된 실행의 대화 ID로 범위가 정해지며 다른 대화 ID를 입력할 수 없습니다. `oldText`는 원문에 **정확히 한 번만** 나타나는 비어 있지 않은 범위 앵커입니다. 겹치는 중복도 모호하므로 거절합니다. 앞뒤 문맥을 포함해 고유하게 지정할 수 있으며 범위 밖 유니코드·CRLF 바이트는 그대로 유지합니다. 빈 `replacement`는 그 범위 삭제입니다. 수정 범위에는 숫자 오프셋 변환을 사용하지 않습니다.

캔버스 수정은 파일 규칙과 별개로 **항상 한 번씩 승인**합니다. 캔버스 내용은 지침이 아닌 대화 데이터이며 도구 권한을 늘리지 않습니다. 공급자 키나 등록된 비밀 값이 포함된 문서는 공개 화면·도구·과거 기록에서 마스킹하고 그 버전의 수정·복원을 차단합니다. 비밀 값이 없는 현재 문서는 과거 기록이 마스킹되어 있어도 편집할 수 있습니다. Node 서버는 기존 공급자 키 마스킹, Rust 서버는 공급자 키와 기존 보관함 비밀 값 마스킹을 사용합니다. 기존 Node 서버의 다른 Rust 기능 미이식까지 해결하는 변경은 아닙니다.

## 호환성과 한계

기존 상태는 캔버스 없이 그대로 열립니다. 캔버스를 처음 저장한 뒤에는 이 필드를 모르는 구버전의 엄격한 스키마가 해당 상태를 열지 못합니다. 롤백이 필요하면 **첫 사용 전에 비공개 데이터 디렉터리를 백업**하세요. 자동 캔버스 이전 상태 백업은 추가하지 않았습니다. 구버전 바이너리로의 실제 롤백 테스트를 했다는 의미는 아닙니다.

편집은 명시적 저장 방식이며 실시간 공동 타이핑·여러 캔버스 문서·코드 실행·자동 병합은 포함하지 않습니다. 서버 재시작 뒤 저장된 문서·기록은 유지되지만 저장하지 않은 브라우저 초안은 영구 보관하지 않습니다. Bot은 브라우저에서 만들어 저장한 캔버스를 읽고 수정하며, 저장하지 않은 새 문서를 대신 생성하는 도구는 없습니다.

## 검증

- 모델·스토어: 이전 상태 로드, CAS·동시 저장 한 승자, 변경 없는 저장, 범위 삭제·중복·겹침·한글·이모지·CRLF, 최근 20개 기록과 새 버전 복원, 재시작, 용량 초과 원자성, 현재/과거 비밀 값, 대화 소유권·삭제.
- HTTP·실제 앱 엔진 + 모의 공급자: 동일 출처·스키마 보호, 실행 중 사용자 저장, 검토 중 충돌·거절·중단·늦은 승인, 파일 자동 허용 규칙이 있어도 캔버스는 승인, MCP 데이터 URI를 텍스트로 보존, 큰 유니코드·CRLF·제어 문자 문서의 모든 페이지가 실제 모델 요청에 완전한 JSON으로 전달됨을 확인하고 끝부분 수정·전체 내보내기를 검증.
- 브라우저: 직접 편집 → Bot 범위 승인 → 되돌리기, 새로고침, 초안 충돌·보존, 같은 버전의 마스킹 전환, 마크다운/코드, 다운로드, 기존 승인 경로의 실제 작업 폴더 내보내기, 데스크톱·390/320px, 그룹·스레드 소유권.
- 실제 모델: 도구 이름을 넣지 않은 첫 문단 축약 요청으로 `gpt-6.1-sol`이 읽기·범위 수정 도구를 선택했습니다. 승인 전 변경 없음, 승인 뒤 더 짧은 첫 문단, 제목·마지막 문단 보존, 되돌리기 새 버전과 정확한 원문 복원을 확인했습니다. 임시 데이터와 합성 문서만 사용했고 기존 설정·대화는 수정하지 않았습니다. [검증 기록](evidence/issue-19/actual-model.json)과 [실제 앱 화면](evidence/issue-19/README.md)을 참고하세요. 이는 한 번의 부분 수정 확인이지 모든 모델의 편집 품질 보장은 아닙니다.
