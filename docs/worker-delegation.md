# 같은 Bot의 하위 작업

`workspace__spawn_worker`는 같은 Bot의 별도 세션에 작업 하나를 맡기는 선택적 앱 도구입니다. 엔진의 네이티브 하위 에이전트는 계속 꺼져 있습니다. Bot은 독립적인 읽기 작업으로 나누는 것이 도움이 될 때만 위임을 제안하고, 평범한 질문이나 작은 작업에는 직접 답하도록 안내받습니다. 일반 1:1 사용자 턴에서만 도구를 노출합니다. 새 위임마다 전체 작업 내용과 읽기 허용 폴더를 보고 **Run worker once**로 한 번 승인합니다. 거절하면 작업이나 숨김 대화를 만들지 않습니다.

## 실행과 결과

- 한 답변에서 서로 다른 작업을 최대 3개 맡깁니다. 앞뒤 공백을 제외하고 같은 작업을 다시 요청하면 이미 만든 작업의 영수증을 돌려주며 재실행하거나 재승인을 요구하지 않습니다.
- 기존 전역 실행 슬롯을 유지합니다. 부모 답변이 성공적으로 끝난 다음 하위 작업을 **한 번에 하나씩** 실행합니다. 실제 병렬 실행이나 부모가 같은 턴 안에서 결과를 기다리는 기능은 아닙니다. 대기열에만 있는 작업은 다른 Bot의 입력창을 잠그지 않습니다. 실제 하위 작업이 실행 중일 때는 기존 전역 실행 제한을 적용합니다.
- 하위 작업은 부모의 Bot 지침, 활성 스킬, 읽기 전용 자료를 사용할 수 있지만 부모 대화 전체를 자동으로 복사하지는 않습니다. 필요한 자료를 작업 설명에 포함해야 합니다.
- 각 작업의 실제 실행 시간은 최대 5분입니다. 기존 추론 무응답 제한도 적용됩니다. 실패·중단된 작업은 자동으로 재시도하지 않습니다.
- 형제 작업이 **모두** 종료되면 성공한 답과 오류를 묶어 부모 대화에서 자동 후속 답변을 한 번 실행합니다. 먼저 끝난 작업만 따로 보고하지 않습니다. 진행 표시에는 최종 답변을 작업당 최대 48 KiB까지 보관하고, 부모에게는 작업당 최대 12 KiB를 인용합니다. 부모 입력에는 잘린 답변을 표시하므로 장문 결과 전체를 전달한다고 가정해서는 안 됩니다.
- 부모의 **작업 중단**은 대기 중인 형제 작업, 실행 중인 하위 작업, 아직 시작하지 않은 결과 정리를 함께 중단합니다. 이미 끝난 결과나 승인해 수행한 이전 작업을 되돌리지는 않습니다. 실행 중인 결과 정리가 중단 요청과 동시에 먼저 완료되면 실제 완료된 답변은 보존합니다.
- 새로고침하면 부모 대화의 접이식 **하위 작업**에서 상태와 개별 결과를 계속 확인할 수 있습니다. 숨김 세션은 대화 기록·주소 선택·HTTP/SSE의 공개 대화 목록에 나타나지 않습니다.

## 권한과 범위

도구 입력은 `{ "task": "맡길 작업의 전체 설명" }`입니다. 작업은 4,000 UTF-16 코드 단위이면서 16 KiB 이하여야 합니다. 모델에는 내구성 있는 작업 영수증만 돌려줍니다. 결과를 기다리며 도구를 반복 호출할 필요가 없습니다.

하위 작업의 깊이는 1입니다. 하위 작업이나 자동 결과 정리 답변에서 다시 위임할 수 없습니다. 그룹·스레드·루틴·다른 Bot의 수신 대화에서도 위임을 받지 않습니다. 새로운 일반 사용자 턴은 새 작업 묶음을 만들 수 있습니다.

하위 작업에는 파일·스킬·기억·지식 자료의 허용된 읽기 도구만 제공합니다. 읽기 허용 작업 폴더는 승인 시점에 고정하며, 대기 중 설정에서 다른 폴더를 선택해도 바뀌지 않습니다. 이 정보가 없는 이전 배치는 현재 폴더를 임의로 물려받지 않고 파일 접근 없이 실행합니다. 파일 수정, 기억/스킬/루틴 변경, Bot 생성, 메시지 전송, 컴퓨터 조작과 사용자 설정 MCP 서버 호출은 허용하지 않습니다. 사용자 설정 MCP 프로세스나 그 자격 증명도 하위 세션에 연결하지 않습니다. 숨김 세션의 승인을 사용자에게 보이지 않게 자동 통과시키지 않습니다.

결과를 정리하는 부모의 후속 답변은 일반 대화와 같이 필요한 작업을 제안할 수 있지만, 모든 쓰기·외부 작업은 기존 자동 허용 규칙과 무관하게 매번 승인을 묻습니다. 하위 작업의 결과는 지시가 아닌 인용된 대화 데이터로 전달합니다.

## 상태와 복구

`WorkerBatch`는 원래 부모 실행/답변, 하위 작업의 숨김 대화/실행 ID, 실행 상태, 제한된 최종 답변과 후속 보고를 연결합니다. 부모 실행이 완료될 때 묶음을 확정하므로 아직 작업을 추가하는 도중에 결과 정리를 시작하지 않습니다. 실행과 보고는 시작할 때 한 저장 변경에서 실행 ID를 결합합니다.

Stop은 저장소에 쓰기 전에 실행 중인 작업과 승인 대기에 먼저 정지 신호를 보냅니다. 디스크 쓰기가 실패해도 현재 실행과 브라우저 작업은 멈추며 저장 오류를 반환합니다. 이 경우 저장하지 못한 취소가 재시작 후에도 유지된다고 보장하지는 않습니다. 정상적으로 저장된 취소는 다시 실행하지 않습니다.

재시작하면 이미 시작했던 하위 작업과 결과 정리는 `interrupted`로 남고 다시 실행하지 않습니다. 부모가 성공적으로 끝내 확정한 묶음의 아직 시작하지 않은 작업은 기존 대기열을 통해 이어서 처리합니다. 부모가 중단된 미확정 묶음은 실행하지 않습니다. 이미 시작한 보고도 다시 실행하지 않습니다.

공개 상태의 선택적 `workerBatches` 필드는 부모의 진행 표시를 위한 데이터입니다. 공개 스냅샷에는 하위 세션의 대화 본문·실행 세션 정보와 자동 보고용 사용자 입력을 넣지 않습니다. 위임한 작업의 설명, 상태, 제한된 답변/오류는 부모 진행 표시를 위해 전달하며 기존 API 키·보관함 비밀 가리기를 적용합니다. 앱 시작 및 새 위임을 받기 전 완료된 묶음의 상세 기록을 정리합니다. 최근 100개 이내이면서 숨김 기록 합계 8 MiB 이내를 보존하고, 오래된 묶음의 진행 카드·개별 결과·숨김 입력/대화와 전용 엔진 폴더는 정리합니다. 부모의 원래 답변과 최종 종합 답변은 지우지 않습니다. 대기·실행·결과 정리 중인 묶음은 대상에서 제외합니다. 새 작업의 용량이 부족할 때는 이 범위 안의 완료 상세도 추가 정리하고 한 번만 다시 시도합니다. 정리가 디스크에 저장된 뒤에만 파일을 지우고, 파일 정리 실패는 다음 시작 때 재시도합니다. 총 1,000개 동시 보존 및 기존 64 MiB 상태 크기 제한은 마지막 안전 상한으로 유지하므로, 사용자 대화 자체가 한도를 채운 경우까지 자동으로 삭제하지는 않습니다.

### 저장 형식

이 기능은 현재 앱의 **Rust 서버**에 포함됩니다. 별도 Node 백엔드나 백엔드 선택 환경변수는 사용하지 않습니다. 이전 데이터는 새 필드의 기본값으로 그대로 열 수 있습니다. 처음 하위 작업 데이터를 저장하기 전 이전 상태를 `state.json.pre-workers.bak`으로 한 번 보관합니다. 새 필드가 들어간 상태는 구형 Rust/Node 백엔드로 열 수 없습니다. 구형 버전으로 돌아가야 한다면 서버를 중지하고 백업 및 이후 기록의 보존 여부를 확인해야 합니다. 실행 중인 사용자 상태를 덮어써서 복원하지 마세요.

## 검증

Rust 저장소와 실제 엔진/모의 공급자 통합 검증은 작업 개수·깊이 제한, 승인/거절, 동일 요청 중복 방지, 부모 종료 전 실행 금지, 순차 실행, 모든 형제 종료 후 단일 보고, 연쇄 취소, 읽기 전용 권한, 시간 제한과 재시작 복구를 다룹니다. 브라우저 검증은 접기/펼치기, 진행 중 중단, 숨김 대화와 입력, 결과 정리, 새로고침 및 작은 화면을 다룹니다.

실제 앱의 변경 전/후 화면과 별도의 실제 모델 확인 결과는 [검증 자료](evidence/issue-14/README.md)에 기록합니다. 모의 공급자로 만든 화면 비교는 실제 모델의 자율적인 도구 선택을 입증하는 자료가 아닙니다.
