# 서버 경유 링크 미리보기

## 사용과 외부 접속

Rust 서버에서 **설정 → 일반 → 링크 미리보기**를 켜면 완료된 봇 답변 아래에 최대 세 개의 링크 카드가 나타납니다. 기본값은 **꺼짐**이며, 서버에 저장한 선택은 브라우저 새로고침과 서버 재시작 뒤에도 유지됩니다. 서버를 공유하는 브라우저 모두에 적용됩니다. 모델 설정이나 작업 폴더 연결 없이도 이 설정을 바꿀 수 있습니다.

켜면 화면 근처에 있는 완료된 답변의 URL에 서버가 접속합니다. 원격 페이지에는 서버 IP와 해당 URL이 전달됩니다. 브라우저의 쿠키·인증 헤더·Referer는 전달하지 않습니다. 브라우저는 메타데이터와 썸네일을 앱의 동일 출처 API에서만 받으며, 썸네일을 표시하려고 외부 서버에 직접 접속하지 않습니다. 원래 링크나 카드를 직접 누르는 것은 별도의 일반 링크 이동입니다.

끄면 즉시 카드를 숨기고 브라우저의 대기 중인 미리보기 요청과 메모리 캐시를 정리합니다. 서버는 비활성화 상태에서 캐시 응답도 거절하며, 다음 외부 접속 전에 설정을 다시 확인합니다. 이미 전송한 외부 요청을 되돌릴 수는 없습니다.

Markdown 링크, 참조 링크, 자동 링크와 일반 텍스트의 HTTP(S) URL을 읽는 순서대로 모으고, fragment를 제거해 중복을 합칩니다. 코드 블록·인라인 코드·이미지 대상·HTML·인용문·사용하지 않은 링크 정의는 요청 대상이 아닙니다. 사용자 메시지와 도구 출력에서도 미리보기를 요청하지 않습니다. 실패한 미리보기는 원래 링크를 대체하거나 답변 자체를 실패시키지 않습니다.

## HTTP 계약

- `GET /api/link-preview?url=<absolute-http(s)-url>` with `X-Grok-Bot: 1` → `{ "url": "최종 URL", "title": "제목", "description": "설명", "imageUrl"?: "/api/generated-images/<uuid>" }`. 외부 요청을 일으키는 GET이므로 다른 사이트의 이미지·링크 이동만으로 실행되지 않도록 전용 헤더가 필요합니다.
- `PUT /api/link-preview/settings` with `{ "enabled": true | false }` → 기존 `AppState` 스냅샷. 다른 변경 API처럼 동일 출처 JSON과 `X-Grok-Bot: 1`이 필요합니다.
- 공개 HTTP/SSE 스냅샷의 `linkPreviewsEnabled`는 Rust 서버에서 항상 boolean입니다. 디스크에는 `true`일 때만 선택 필드를 기록하며, 기존 파일에 없으면 `false`입니다.
- 꺼진 상태와 비공개 목적지는 403, 잘못된 URL은 400, 큰 응답은 413, HTML이 아닌 페이지는 422, 다운로드 실패는 502, 전체 기한 초과는 504, 동시 요청 한도 초과는 503입니다. 썸네일만 실패하면 이미지 없는 정상 카드로 반환합니다.

기존 Node 서버는 이 API를 제공하지 않으므로 UI에서 설정을 비활성화합니다. 해당 설정 필드만 추가된 호환 상태 파일은 Node 저장소에서도 읽고 보존하지만, 미리보기 지원을 광고하지 않습니다. 다른 Rust 전용 기능의 상태 파일까지 Node로 되돌릴 수 있다는 의미는 아닙니다.

## 네트워크 보안 경계

1. 길이 4,096 byte 이하의 HTTP(S) URL만 받습니다. 인증 정보·공백·제어 문자·역슬래시·0번 포트는 거절합니다. URL 파서가 정규화한 IP literal도 같은 검사를 받습니다.
2. 각 외부 접속 전에 DNS를 한 번 조회하고 **모든** 응답을 검사합니다. 공인 주소와 사설 주소가 섞여 있어도 전체를 거절합니다. IPv4 특수 목적 주소와 IPv6의 loopback·ULA·링크로컬·multicast·mapped/NAT64·문서용·기타 비공개 범위를 차단합니다. 관리형 브라우저의 기존 공인 IP 판별 함수를 재사용합니다.
3. HTTP 클라이언트에는 검증한 IP만 반환하는 전용 resolver를 주입합니다. 같은 이름을 다시 시스템 DNS로 조회하거나 다른 이름으로 대체할 수 없습니다. HTTPS는 원래 호스트 이름의 인증서를 검증합니다.
4. 자동 리다이렉트와 환경 프록시를 끕니다. 리다이렉트마다 새 URL을 검증하고 DNS를 재검사합니다. 썸네일도 동일한 fetch 경로·정책·공유 시간/리다이렉트 한도를 사용합니다. 요청 쿠키나 자격 증명은 복사하지 않습니다.
5. 페이지의 `og:url`, canonical 링크와 `<base>`는 목적지로 신뢰하지 않습니다. 상대 썸네일은 실제 최종 페이지 URL 기준으로 해석합니다. HTML이나 메타데이터의 스크립트를 실행하지 않습니다.

이 정책은 DNS/IP 기반 목적지 차단입니다. 공개 서버가 자체적으로 다른 네트워크에 요청을 중계하는 행동까지 통제하지는 못하며, 로그인·쿠키가 필요한 페이지의 미리보기도 보장하지 않습니다. 일반 앱의 개인용·신뢰 네트워크 배포 경계는 그대로입니다.

## 자원 제한과 저장

| 항목 | 한도 |
| --- | --- |
| 전체 다운로드 기한 | 8초: DNS·모든 페이지/썸네일 리다이렉트·메타데이터 처리·이미지 저장 포함 |
| 페이지 본문 | 512 KiB, Content-Length와 스트리밍 누적 크기 모두 검사 |
| 썸네일 본문 | 2 MiB, 동일 크기 검사 |
| 리다이렉트 | 페이지와 썸네일을 합쳐 최대 5회 |
| 동시 작업 | 최대 8개, 초과 요청은 대기열을 무한히 늘리지 않고 거절 |
| 서버 캐시 | 최대 128개, 성공 15분 / 실패 30초, 같은 URL의 동시 요청 합침 |
| 브라우저 캐시 | 최대 100개, 성공 5분 / 실패 30초, 대기 요청 합침 |
| 답변당 카드 | 중복 제거 후 처음 3개 |

압축된 응답은 받아들이지 않으며 `Accept-Encoding: identity`로 요청합니다. JavaScript로만 생성되는 내용은 실행하지 않습니다. Open Graph 제목·설명을 우선하고 `<title>`과 description으로 대체합니다. CPU 작업도 제한하기 위해 페이지의 첫 64 KiB와 최대 2,048개 마크업 구분자 범위만 파싱하고, 개별 텍스트 후보는 8 KiB / 256개 구분자로 제한한 뒤 선형 순회로 정리합니다. 이 범위를 넘겨 배치된 메타데이터는 표시하지 못할 수 있습니다. 파서·이미지 저장·시스템 DNS처럼 시작 뒤 취소할 수 없는 작업은 응답 기한이 지나도 실제 완료될 때까지 실행 슬롯을 유지합니다.

썸네일은 PNG·JPEG·GIF·WebP signature를 확인한 뒤 기존 생성 이미지 저장 방식으로 무작위 UUID 아래에 저장합니다. 브라우저에는 원격 썸네일 URL을 돌려주지 않습니다. 생성 이미지 경로의 기존 no-sniff·동일 출처·sandbox 헤더를 사용하며 SVG/HTML은 썸네일로 제공하지 않습니다. 이미지가 없거나 손상되면 텍스트 카드로 남습니다.

메타데이터 캐시는 메모리 전용입니다. 캐시 만료·제거·설정 끄기 때 이 기능이 만든 썸네일을 정리하며, 저장된 메시지가 해당 로컬 URL을 참조하면 기존 생성 이미지 보관 정책에 넘깁니다. 비정상 종료 뒤 남은 참조 없는 이미지는 기존 시작 시 정리 과정의 유예 기간을 따릅니다. 원본 페이지 본문은 저장하지 않습니다.

## 검증과 화면 증거

- URL 선택/상태 호환 회귀: `npx tsx --test tests/link-preview-*.test.ts tests/frontend-state.test.ts tests/store-ordering.test.ts`.
- Rust 보안/캐시/설정 회귀: 새 미리보기 모듈의 단위 테스트와 HTTP 통합 테스트.
- 브라우저: `GROK_BOT_BACKEND=rust npx playwright test tests/link-previews.spec.ts tests/link-preview-privacy.spec.ts`.
- [Before / After와 재현 시나리오](evidence/issue-18/README.md).

테스트의 HTTP 사이트와 모델은 모두 격리된 로컬 fixture입니다. e2e에서만 debug 바이너리를 `NODE_ENV=test`로 실행하고 `GROK_BOT_LINK_PREVIEW_TEST_ORIGINS`에 JSON 배열로 명시한 loopback HTTP origin을 허용합니다. 호스트 이름·wildcard·임의 포트 허용은 없으며 release 빌드에서는 환경 값으로 이 예외를 켤 수 없습니다. 실제 외부 사이트에 대한 SSRF 탐침은 수행하지 않습니다.
