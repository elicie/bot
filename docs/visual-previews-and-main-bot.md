# 시각화·미리보기·메인 Bot (2차)

작성일: 2026-11-01

원본 Grok Bot 0.78.1의 문구("시각화 확대", "시각화 미리보기 닫기", "이 시각화를 불러올 수 없어요", "이 시각화를 시작하는 데 10초 넘게 걸렸습니다", "이 시각화에서 스크립트 오류가 발생했어요", "이 시각화는 사용할 수 없습니다", "다이어그램 미리보기", "다이어그램 전체 화면으로 열기", "미디어 미리보기", "이미지 전체 화면으로 열기", "미디어 다운로드", "메인 Bot", "메인 Bot 선택", "메인 Bot을 바꿀 수 없어요")와 RPC 이름(`getMainAgent`, `setMainAgent`, `ensureDefaultMainAgent`; 메인 Bot을 정하면 고정)만 참고했습니다. 원본 코드·CSS·자산은 쓰지 않았습니다.

## 시각화 (`web/Visualization.tsx`, `web/visualization-document.ts`)

Bot 답변의 ```` ```html ````, ```` ```svg ````, ```` ```visualization ```` 코드 블록이 미리보기 카드가 됩니다. 카드에는 "코드 보기"/"미리보기" 전환과 "시각화 확대"(전체 화면, "시각화 미리보기 닫기"·Esc로 닫기)가 있습니다. 답변이 스트리밍되는 동안에는 코드가 0.4초 동안 바뀌지 않을 때 실행하고, 화면 근처에 올 때만 프레임을 만듭니다.

격리 규칙:

- `<iframe sandbox="allow-scripts" srcdoc>`만 사용합니다. `allow-same-origin`, `allow-top-navigation`, `allow-forms`, `allow-popups`, `allow-modals`가 없어 앱 문서·저장소·쿠키를 읽지 못하고, 팝업·폼·최상위 이동을 하지 못합니다. 권한 정책(`allow`)으로 카메라·마이크·위치·클립보드·전체 화면 등도 막습니다.
- 문서의 첫 요소가 CSP입니다: `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; media-src data: blob:; form-action 'none'`. 코드보다 먼저 파싱되므로 fetch/XHR/WebSocket, 외부 스크립트·스타일·이미지·프레임·워커가 모두 차단됩니다. 앱 API(`/api/state`)도 읽을 수 없습니다.
- 앱 페이지(`index.html`)는 `frame-src 'none'`을 둡니다. 프레임 안의 CSP로는 막을 수 없는 자기 이동(`location` 변경, `<meta http-equiv="refresh">`)을 브라우저가 거절하고, 카드는 "이 시각화를 불러올 수 없어요"를 보여 줍니다. 링크 클릭은 프레임 안에서 먼저 취소하고 "시각화 안의 링크는 열 수 없어요."라고 알립니다.
- 먼저 실행되는 부트스트랩 스크립트가 로드 완료·스크립트 오류·크기·차단된 요청 수·Esc를 프레임별 nonce와 함께 보내고 스스로 지웁니다(코드가 nonce를 읽지 못함). 앱은 `event.source`가 그 프레임이고 nonce가 맞는 메시지만 받습니다. 다른 프레임이나 페이지가 보낸 메시지는 무시합니다.
- 상태 문구: 10초 안에 로드되지 않으면 "이 시각화를 시작하는 데 10초 넘게 걸렸습니다"(프레임 제거, 다시 시도), 스크립트 오류는 "이 시각화에서 스크립트 오류가 발생했어요"와 오류 내용·줄 번호, 200,000자를 넘거나 비어 있으면 "이 시각화는 사용할 수 없습니다"(코드로 표시).
- d3: 앱에 이미 있던 d3 7.9.0 빌드(ISC, `package.json`에 명시)를 네트워크 없이 문서에 직접 넣습니다. ```` ```visualization ```` 블록과 `d3.`를 쓰는 코드에만 넣고, 내용이 `<script>`를 끝낼 수 없는지 확인한 뒤에만 넣습니다. three.js·Chart.js 같은 다른 라이브러리는 없습니다(외부 `<script src>`는 CSP로 차단되어 스크립트 오류로 표시).

브라우저 한계(웹 페이지에서는 고칠 수 없음, 원본은 Electron 전용 스킴과 세션 제어로 처리):

- Chromium은 WebRTC에 CSP를 적용하지 않습니다. 부트스트랩이 WebRTC 생성자를 지우지만, 중첩된 about:blank 프레임을 거치면 다시 얻을 수 있습니다.
- 스크립트로 프레임을 이동하면 Chromium이 `frame-src`로 거절하기 전에 대상 주소에 연결(DNS 조회·TCP 연결, HTTP 요청은 보내지 않음)합니다. 경로·쿼리는 나가지 않지만 호스트 이름은 DNS로 나갈 수 있습니다. Navigation API로 먼저 취소하는 방법은 불투명 출처 문서에서 이벤트가 발생하지 않아 쓸 수 없습니다.
- 페이지의 샌드박스 프레임은 한 프로세스를 공유합니다. 무한 반복하는 시각화는 제거한 뒤에도 다른 시각화를 멈추게 하므로, 시간 초과 문구에 새로고침 안내를 덧붙였습니다.

## 다이어그램·미디어 미리보기 (`web/Previews.tsx`)

- Mermaid 다이어그램을 누르거나 "다이어그램 전체 화면으로 열기" 버튼(키보드 포커스·마우스 올림 때 표시, 터치 화면에서는 항상 표시)으로 "다이어그램 미리보기"를 엽니다.
- 보낸 이미지 첨부와 답변의 Markdown 이미지는 "이미지 전체 화면으로 열기"로 "미디어 미리보기"를 엽니다. Markdown 이미지는 `data:image/…;base64`와 이 앱의 첨부 URL(`/api/conversations/:id/attachments/:id`)만 표시하고, 그 밖의 주소는 지금처럼 `[이미지 · 설명]` 텍스트로 두어 요청하지 않습니다.
- 미리보기는 최상위 모달 대화 상자입니다. 닫기 버튼에 포커스가 가고, Tab은 안에서 순환하며, Esc·닫기 버튼("다이어그램 미리보기 닫기", "미디어 미리보기 닫기")으로 닫으면 연 버튼으로 포커스가 돌아갑니다. 축소·확대·화면에 맞추기 버튼, `+`/`-`/`0` 키, Ctrl/⌘+휠로 확대·축소하고 스크롤로 이동합니다. 첨부·Markdown 이미지는 "미디어 다운로드" 링크가 있습니다.

## 메인 Bot (`crates/store/src/main_bot.rs`, `crates/core/src/main_bot.rs`, `web/MainBot.tsx`)

- `state.json`의 `mainBotId`에 하나만 저장합니다. 값이 없으면(기존 데이터 전부) 첫 Bot이 메인 Bot이며, 기본값을 기록하려고 파일을 다시 쓰지 않습니다. 공개 상태의 `mainBotId`도 저장된 값을 그대로 보여 주고(없으면 첫 Bot), 화면(`web/state.ts`의 `mainBotId`)과 서버(`State::main_bot_id`)가 같은 규칙으로 정합니다. 없는 Bot을 가리키는 `state.json`은 읽기를 거부합니다.
- `POST /api/bots/:id/main` `{}`로 바꿉니다. 이미 메인 Bot이면 아무것도 쓰지 않습니다. 다른 Bot 변경처럼 실행 중에는 거절합니다(409). 새 메인 Bot은 숨김이 풀리고 고정되며(원본의 `setMainAgent`도 고정), 이전 메인 Bot은 사이드바 위치가 바뀌지 않도록 고정 상태로 남습니다.
- 사이드바에서 메인 Bot은 고정 그룹의 맨 앞에 "메인 Bot" 표시와 함께 나옵니다. 접근성 이름은 Bot 이름 그대로이고 "메인 Bot"은 설명(`aria-describedby`)으로 읽힙니다.
- Bot 메뉴의 "메인 Bot 선택"으로 대화 상자를 열어 고릅니다(그 Bot이 미리 선택됨). 실패하면 "메인 Bot을 바꿀 수 없어요."와 서버 오류를 보여 줍니다.
- Bot을 고르지 않은 첫 화면(주소에 Bot이 없을 때)과 새 루틴의 기본 Bot은 메인 Bot입니다.
- 삭제 결정: 메인 Bot도 삭제할 수 있고, 삭제하면 남은 첫 Bot이 메인 Bot이 됩니다. 삭제 확인 창이 "이 Bot은 메인 Bot이에요. 삭제하면 “…”이(가) 메인 Bot이 돼요."라고 미리 알립니다. 마지막 Bot은 지금처럼 삭제할 수 없습니다. 기존 삭제 규칙·테스트(첫 Bot 삭제)와 맞추려고 보호 대신 재지정을 골랐습니다.
